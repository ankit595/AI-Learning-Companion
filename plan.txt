PHASE 3 — BETTER RAG
----------------------------------------------------------------

✅ Step 10: BM25 hybrid search in retriever.py
   → EnsembleRetriever: BM25 (keyword) + Chroma MMR (vector), weights=[0.5, 0.5]
   → Better for exact term matching (function names, error codes, acronyms)
   → BM25 index built in-memory per-call from the same user_id/topic-filtered
     subset pulled out of Chroma (BM25Retriever has no native metadata filter)
   → Falls back to vector-only retriever if no docs match the filter yet
     (empty index) or if BM25 construction raises for any reason
   → BUG FIX (found while implementing this): get_retriever()'s Chroma
     `where` filter previously broke when BOTH user_id AND topic were passed
     together (Chroma requires "$and" for multi-key filters) — fixed for
     both the vector retriever and the new BM25 subset query
   → New dependency: rank_bm25 (added to requirements.txt)
   → Uses langchain_classic.retrievers.ensemble.EnsembleRetriever (LangChain
     1.x moved EnsembleRetriever out of langchain_community into
     langchain_classic) + langchain_community.retrievers.BM25Retriever

❌ Step 11: evaluation/ragas_eval.py
   → RAGAS metrics: faithfulness, answer relevancy, context precision/recall
   → Run against test question set to measure RAG quality
   💡 DEFERRED — pure measurement/testing tool, not user-facing. Not required
      to consider the app "done"; revisit only when actively tuning RAG
      quality and wanting objective before/after scores.
